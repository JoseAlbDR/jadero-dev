Code map

How the repo fits together today: which package depends on which, what the api container injects at runtime, the two module shapes new code copies, how api boots, what a request passes through and how one trace id follows it, how the build, pnpm dev and the checks run, what a page request passes through in web, how an event crosses the broker from api to agent, and how each service reaches its own database: the connection, one transaction per use case, the unit of work and the migrations. Click or tap any box for what it is, how it works, why it was built this way, and where the code lives. Arrows start faded: pick one or more boxes in a graph's Focus row (or click them) to see only their arrows, and switch arrow kinds off under Layers.

How to update this map

  1. All content lives in the JSON block <script id="map-data"> near the end of this file. The rendering code below it should not need changes.
  2. Add a box: add an entry to nodes (label, sub, kind, status, wp, what, how, why, files), then place it in a figure: place for a graph (x, y, width, height in the figure's viewBox), or add its id to steps or cards. A steps figure counts from 1 unless it sets "start".
  3. Add an arrow: add { "from", "to", "label", "kind" } to the figure's edges. Kinds: dep, dev, imports, provides, injects, consumes, throws, extends, lifecycle, flow, planned, forbidden. Add "hideLabel": true when a gap is too small for the label. Use via points to route around a box.
  4. When a planned box becomes real, change its status to real and its edges from planned to their real kind.
  5. Focus chips and layer toggles need no JSON: every graph gets a chip for each placed box that has an arrow, and a layer toggle for each edge kind it uses. Arrows drawn with points (no from/to) are annotations and never fade. The viewer's selection and layers are kept per figure in the browser (keys codemap:fig:<section id><figure index>), so moving a figure only resets them.
  6. A new event type gets a card in section 8's event catalog, its path in the graph there (producer, exchange, consumer queues, tables), and an entry under that graph's events, keyed by the card's node id: { "summary", "hops": [{ "edge", "caption" }], "failure": [edge indexes], "failureNote" }. edge is the index in the figure's edges array (counting from 0), so adding or removing an edge above it shifts the numbers: update them in the same change. A card whose id has an events entry becomes the explorer's toggle; the event's details open from the explorer's button.
  7. Bump meta.lastUpdated, save in docs/architecture/code-map.html, and republish the artifact from the same file.
