How the repo fits together today: which package depends on which, what the api container injects at runtime, the two module shapes new code copies, how api boots, what a request passes through and how one trace id follows it, how the build, pnpm dev and the checks run, and what a page request passes through in web. Click or tap any box for what it is, how it works, why it was built this way, and where the code lives.

How to update this map

  1. All content lives in the JSON block <script id="map-data"> near the end of this file. The rendering code below it should not need changes.
  2. Add a box: add an entry to nodes (label, sub, kind, status, wp, what, how, why, files), then place it in a figure: place for a graph (x, y, width, height in the figure's viewBox), or add its id to steps or cards. A steps figure counts from 1 unless it sets "start".
  3. Add an arrow: add { "from", "to", "label", "kind" } to the figure's edges. Kinds: dep, dev, imports, provides, injects, consumes, throws, extends, lifecycle, flow, planned, forbidden. Add "hideLabel": true when a gap is too small for the label. Use via points to route around a box.
  4. When a planned box becomes real, change its status to real and its edges from planned to their real kind.
  5. Bump meta.lastUpdated, save in docs/architecture/code-map.html, and republish the artifact from the same file.
