# WP-16: Site pages

WP-16 is a frontend work package (tag `frontend`): result-only, no explainer and no explain-back (AGENTS.md section 5). This file exists only because the learning gate also covers the repo tooling files, and the pages need new entries in the `pnpm-workspace.yaml` catalog.

## Decision

The owner chose the D-38 fast path on 2026-10-10: nothing new to learn in the tooling changes of this WP. They are catalog entries in `pnpm-workspace.yaml` for the self-hosted Geist fonts (`geist`, ADR-045) and the safe Markdown pipeline (remark, rehype, `rehype-sanitize`, ADR-011), added in the step that first uses each one, plus per-package config in `apps/web` and `packages/ui`. No service code is touched.

## Choices recorded with the owner (2026-10-10)

- CSP: nonce-based as ADR-047 says. Next.js 16 renders every page with a nonce per request (no static pages, ISR or PPR), so the pages call `connection()` and cache the API responses with `fetch` `revalidate` and tags; never `force-dynamic`, which drops that cache.
- Work-log pages: D-50 stays (entries are English only). Under `/es` and `/de` the page shows the English entry with `lang="en"`, a translated note and a canonical to `/en`. Translating the entries is tracked in issue #116, outside WP-16.
- "Ask about this" and the home terminal: visible and resting until the chat of WP-25; the button carries the question to the terminal prompt, nothing is sent.
- Pillar strip and evidence map: fixed site copy in `messages/{es,en,de}.json` from report section 2A, linking to pages by slug; no backend field.
