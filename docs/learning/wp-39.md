# WP-39: Build journal and /now

WP-39 is tagged `frontend`, but part of it lands under learning paths (`apps/api`, `packages/contracts`): the `journal` post kind, the `Now` singleton and the journal import command. The owner chose the D-38 fast path on 2026-10-24: every pattern here was met in WP-12 (aggregates with per-locale revisions, a published pointer, the read-only public API, the seed command), so there is no full explainer and no explain-back. This file records the three decisions that apply ADR-034 (option A, D-57).

## D1. Journal is a kind of Post

`content.posts` gains `kind` (`post` or `journal`, default `post`) and a nullable integer `wp`. Migration 0004 adds `CHECK ((kind = 'journal') = (wp IS NOT NULL))` and a partial unique index on `wp` where `kind = 'journal'` (one journal post per WP). The domain enforces the same rule in `Post.create`. `GET /v1/content/:locale/posts` takes `?kind=` (default `post`, so the blog does not list journal posts), and the contracts carry `kind` and `wp`.

Discarded: a separate `JournalEntry` aggregate with its own revision tables. It would win if journal posts got rules of their own; today they share every rule of a post plus one field.

Patterns: discriminator column (single-table inheritance), invariant enforced in the domain and as a database CHECK (defense in depth).

## D2. Now is a singleton aggregate with revisions

`Now` follows `Profile`: one row, one localized document per locale (Markdown `body`), revisions and a published pointer per locale, read through `GET /v1/content/:locale/now`. The /now page composes three reads: the Now text, the current WP and the latest three journal posts. The current WP is derived from the latest published journal post (shown as the last finished WP); what is in progress goes in the Now text. A hand-edited WP field was discarded because it goes stale on its own; a field on `Profile` was discarded because the two change at very different rates.

Patterns: singleton aggregate, read-side composition.

## D3. A journal import command now, not after the admin (WP-17)

`pnpm --filter @jadero/api journal:import` reads `docs/journal/*.md`, validates the front matter with Zod (`wp`, `title`, `status`, `date`, `locale`) and upserts by `wp` through the existing use cases: it creates the journal post or appends a draft revision in that locale only when the content changed (idempotent). It never publishes. A file that still holds an `<!-- owner: check -->` marker is refused. `journal:publish <wp> <locale>` publishes one locale on the owner's command until the admin exists. The draft assistant through the chat port (optional in ADR-034) is deferred to R2.

Discarded: waiting for WP-17, which blocks R1 on the admin and leaves the drafts idle. The command is one more driving adapter on the same application ports, so the admin later adds a second one without throwing code away.

Patterns: ports and adapters (a CLI as a driving adapter), idempotent import, human in the loop for generated drafts.

## Implementation choices

- Migration generated by `drizzle-kit generate`, reviewed, never edited after it is applied.
- The journal feed reuses the posts feed index; the kind filter is a column in the same query.
- Seed data adds one Now document per locale and one journal post.
- Web pages reuse `PostList` and the blog post page; strings in `messages/{es,en,de}.json`.

## Step log

- Step 2 (journal kind on Post, D1). What just happened: migration 0004 adds `content.posts.kind` (default `post`) and `wp` with three CHECKs and the partial unique index `posts_journal_wp_unique`; `Post.create` throws `JournalWorkPackageInvalid` on a kind and WP that disagree; `PostRepository.findJournal(wp)` joins the port, its contract suite, the Drizzle adapter and the fake; `GET /v1/content/:locale/posts` takes `?kind=` (default `post`) and every post DTO carries `kind` and `wp`. Why: a journal post is a post plus one field, so a discriminator column keeps one aggregate and one feed, the same rule lives in the domain and in the database (defense in depth), and the blog stays journal-free by default while step 4's import can upsert by WP.
- Step 3 (Now singleton, D2). What just happened: a `Now` aggregate (per-locale `NowDocument { body }`, complete when the body is filled, no archive) joins the generic content use cases as localized type `now`, with `NowRepository`, its contract suite, a Drizzle adapter and an in-memory fake, both units of work and the seed (one Now page in es, en and de, plus the published journal post of WP-12); migration 0005 adds `content.now` (unique index `now_singleton` on a constant), `now_revisions` and `now_translations` like the profile's three tables, and grants `content_reader` SELECT on the two the query reads; `GET /v1/content/:locale/now` returns `nowDto` (`locale`, `body`, `publishedAt` from the translation's `published_at`) with the public cache headers, 304 on a matching ETag and a no-store 404 problem when nothing is published. Why: the /now text changes far more often than the profile, so it is its own singleton with the same revisions, publish guards and German fallback instead of a field on `Profile`, and "updated on" reads the time the published pointer last moved, so no document field can go stale; the reader role has no default privileges, so a new table stays private until a migration grants it.
- Step 4 (journal import and publish commands, D3). What just happened: `ImportJournalPost` upserts a journal draft by WP in one unit of work (creates the post with canonical slug `journal-wp-<N>` and a draft revision, appends a revision only when the document differs from that locale's latest, else `unchanged`) and `PublishJournalPost` finds the post by WP and hands the named locales, or every locale in `draft` or `changed`, to `PublishContentItem`; `src/journal/` parses each `docs/journal/*.md` (front matter with `yaml` and Zod, the title heading dropped, slug from the title, excerpt from the first paragraph, no tags), refuses a file with `<!-- owner: check -->`, and `journal:import [dir]` and `journal:publish <wp> [locales...]` print one line per file or publish and exit 1 on any refusal; unit tests on the fakes, an int test on Postgres (created then unchanged; publish refused without es, then es and en live). Why: the command is one more driving adapter on the same application ports the admin will call (WP-17), so the import passes every domain rule, a second run is a no-op (idempotent import), and nothing goes public without the owner's explicit publish (ADR-034, human in the loop) under the same D-20 guard as any content.
- Step 5 (web journal pages, implementation choice "web pages reuse `PostList` and the blog post page"). What just happened: `apps/web` gains `/[locale]/journal` and `/[locale]/journal/[slug]` (the same word in every locale, like `/blog`); `getPosts` now always sends `?kind=` (`post` from the blog, `journal` from the journal), both list pages render a shared `PostIndex` and both post pages a shared `PostArticle`, each journal card and page shows a `WP-<n>` label, and `loadPostPage` takes the route's kind, so a journal slug under `/blog` or a blog slug under `/journal` is a 404 and the translated-slug lookup walks only that kind's list; the footer links the journal, the sitemap lists `/journal` and each journal post per published locale with its hreflang alternates, messages carry a `JournalPage` namespace in es, en and de, and the e2e stub serves `journal.json` behind `?kind=journal`. Why: a journal post is a post (D1), so the site reuses the blog's pages and only the route and the kind differ, while one URL per post keeps canonical links honest; the `/now` footer link waits for step 6 because the footer adds a link only with its page.
- Step 6 (web /now page, D2). What just happened: `apps/web` gains `/[locale]/now` (the same word in every locale), which reads `getNow` (new in the content client, cached under `content:now`, its 404 problem returned as `null` instead of the page's 404) and the journal feed in parallel, renders the Now text through the safe Markdown pipeline with "Updated <date>" from `publishedAt` (or a localized note when the locale has none), then a "last finished work package" tile and the latest three journal posts (`PostList` with `h3` titles) from `nowJournal`, which takes the feed's newest post; both blocks hide when the journal is empty; the footer links Now, the sitemap lists `/now` with its hreflang alternates, a `NowPage` namespace lands in es, en and de, and the e2e stub serves `now.json` (no German text, so the suite covers the empty state). Why: D2 composes the page on the read side from data that already exists, so the current work package is derived from what was published and cannot go stale, and a missing Now text degrades one card instead of the whole page.
- Review fixes (PR #161). What just happened: `getPosts` keeps only the items of the kind it asked for and passes the API's cursor through, so a filtered page may be shorter or empty; the /now page reads the journal feed through `readNowJournal`, which turns a `ContentApiError` into the empty journal (no new log line) and rethrows anything else; `SeedContent` skips a journal post whose work package `findJournal` already finds, so `db:seed` after `journal:import` of WP-12 no longer fails with 23505 (the int test showed `posts_slug_unique` firing before `posts_journal_wp_unique`); `parseJournalDraft` refuses a title or body (so the excerpt) holding an em dash with `refused: holds an em dash; use a comma, colon or new sentence`, never quoting the text, and none of the current `docs/journal/` drafts holds one. Why: an `api` older than WP-39 ignores `?kind=` and its posts default to `post`, so filtering in `web` keeps blog posts off `/journal` whichever service deploys first (expand/contract, defense in depth); D2 says the page always renders, so the journal blocks degrade like the Now text does; the seed's "create if missing" must count the WP slot the import may have taken, like a singleton; ADR-034 puts journal posts under the content rules, so the import enforces them at the boundary instead of trusting the drafts.
